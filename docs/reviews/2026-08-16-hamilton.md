# Safety review, 2026-08-16

Five independent reviews of the whole system (~26k lines), each applying a
failure-mode lens to one domain. Findings below were verified by reading the
code and, where marked **[proven]**, by running the failure against the live
dev stack.

**Verdict: not fit for a production fleet until the CRITICAL section is closed.**

The architecture is sound and several hard things are done unusually well (see
the last section). The defects are concentrated, specific, and fixable. None of
them are "rewrite it".

## The through-line

Every domain produced a variant of the same defect:

> The system cannot distinguish **healthy** from **alive but deaf**.

- An agent whose NATS connection is closed keeps heartbeating into the void.
- A dispatcher whose consumer died logs "consumer running".
- A device that never comes back gets one alert attempt, then silence.
- An alert suppressed by cooldown leaves no row, so the dashboard looks calm.
- A fact that disappears and returns is never mentioned again.

In each case the failure is indistinguishable from normal operation. That is
the property to fix, not just the individual bugs.

## CRITICAL

| # | Defect | Consequence |
|---|---|---|
| 1 | **[proven]** `session_id` is interpolated into NATS subjects unvalidated. `session_id=">"` makes the agent's own subscribe fail, and nats.go closes the connection permanently. Process stays alive, so no service-manager restart. | One request makes a machine **permanently unmanageable**. Send it fleet-wide and every endpoint goes dark until physically touched. |
| 2 | **[proven]** `session_id="*"` subscribes to every session's input. | A root PTY receives other admins' keystrokes. Also consumes their flow-control acks, disabling backpressure. |
| 3 | **[proven]** `record_facts` selects current beliefs by `recorded_during` only, ignoring `valid_during`. Correction rows (closed valid range, open belief) are treated as current. | A fact that goes away and comes back is compared equal to its own tombstone, written as "unchanged", and stays **invisible forever**. Verified: republished 3 patches, zero written, still invisible. |
| 4 | **[proven]** Any enrolled agent may `SUB _INBOX.>`. All agents share the `$G` account and the default inbox prefix. | One compromised endpoint reads every job envelope for every machine, including script bodies that run as root. |
| 5 | `$JS.API.CONSUMER.CREATE.JOBS.{durable}.>` lets an agent choose its own filter subject. | An agent creates a consumer filtering `jobs.*` and drains the whole fleet's work. Victims never receive their jobs; nothing alarms. |
| 6 | Alert cooldown returns **before** the INSERT, and `last_fired_at` is never cleared on resolve. | A second, genuinely new incident inside the cooldown produces **no alert row at all**. Not delayed, absent. |
| 7 | Job rows are flushed, then published to JetStream, then committed. A commit or mid-batch publish failure leaves jobs executing with no record. | Scripts run as root on N machines with no run row, no output, and no audit entry. Same shape in `queue_patch_install`. |
| 8 | Windows: `Install` returns `res` on the ctx-cancelled path while the COM thread still writes it. Concurrent map write is a Go runtime throw. | Cancelling a patch job **kills the agent process**; `recover` cannot catch it. Racing every Windows agent at once. |
| 9 | pacman ids without `=` fall through to a bare package name with no validation. | `-Syu` becomes a full unattended system upgrade, unapproved, then reports "failed". |
| 10 | `TrustedKeys` skips a blank `EmbeddedPublicKey` instead of failing. The goreleaser header instructs setting it empty for snapshots. | A build with an empty embedded key trusts **whatever key the server supplies**, inverting the update trust model. |

## HIGH (selected)

- **Clock skew poisons ingest forever** **[proven]**: agent `ts` is unvalidated and used as a partition key. One skewed endpoint = infinite nak loop (measured: 12 failures in 30s). No `max_deliver` on any consumer, so nothing ever gives up.
- **[proven]** `GET /api/v1/devices/sessions/recent` has no authentication. Anonymous callers get device UUIDs and admin shell history.
- **No revocation exists.** `status=retired` is checked but never set by any code path; `rotate_creds` is unimplemented; the issued JWT has no `exp`. A stolen agent cannot be cut off.
- **Self-update is unreachable.** `agent.update` still replies "unsupported"; nothing publishes it. The whole signed-update pipeline is dead code, while docs describe it as shipped.
- **Rollback cannot fire for the likeliest bad build**: `CheckAndRollback` runs after config load, so anything crashing earlier loops forever with the good binary sitting beside it.
- **"Healthy" means "survived 60 seconds"**, then the backup is deleted. A build that connects but does nothing is declared good, permanently.
- **A job whose script leaves the process group never completes**: drain waits on pipes the SIGKILL didn't close. No result, no timeout, permanent leak of goroutines and the staged script body.
- **The durable job consumer stops permanently** on a terminal pull error while `consume()` parks on `ctx.Done()`. Recreate the JOBS stream and the fleet silently stops executing jobs.
- **Disabling a rule strands its firing alerts forever** (resolve paths only iterate enabled rules).
- **Heartbeat-missed is edge-triggered**: the sweep returns only devices that *just* transitioned, so a device suppressed by cooldown is never retried. Offline forever, alert page empty.
- **Notification config errors destroy notifications.** A channel disabled for maintenance discards every alert queued in that window.
- **Shell flow control leaks acks**: the queue is bounded in frames while the window is bounded in bytes, so drops are routine, dropped bytes are never acked, and the PTY eventually pauses forever. The keepalive pings on a timer regardless of progress, so the agent's watchdog is fed by a task that cannot detect the failure.
- **Nothing supervises** the heartbeat consumer, offline sweep, partition maintenance, or outbox loop; a raised exception leaves a healthy-looking process with that function silently gone.

## What is genuinely well built

Worth protecting through the fixes:

- **Dedup lives in the database.** The partial unique index on `(rule_id, device_id) WHERE state <> 'resolved'` and the GiST exclusion constraints on the fact tables are real guarantees, not conventions. The exclusion constraint is what turns several of the bugs above into loud failures instead of silent corruption.
- **No shell anywhere in the patch path.** Every invocation is `exec.CommandContext(name, args...)`. Classic injection genuinely does not exist.
- **Verification against the system, not the exit code.** apt re-queries dpkg, dnf re-queries rpm, pacman diffs before/after, WUA reads per-update result codes. The exit-code traps everyone gets wrong (dnf 100, needs-restarting 1) are each handled deliberately.
- **The COM thread discipline** is textbook: one locked OS thread, STA chosen with the tradeoff reasoned out, panics contained. Finding 8 is state escaping that discipline, not a flaw in it.
- **`agent_id` is validated as a UUID before subject interpolation**, so the injection everyone worries about is impossible. (`session_id` is the one that was missed.)
- **Ingest derives identity from the NATS subject, not the payload**, and cross-checks the envelope. Cross-agent forgery is properly blocked.
- **Every MCP tool is scope-gated and audit-logged**, and confirm gating cannot be bypassed: the `if not confirm: return` precedes every write.
- **Env scrubbing, interpreter allowlists, 0700 staging under the root-only state dir**, and `safeName` genuinely defeating traversal.
- **Deterministic jitter**, atomic state persistence, idempotent telemetry ingest, `max_msgs_per_subject=1` making stale inventory replay impossible.

## The tests that gave false confidence

Three tests passed while the thing they claim to verify was broken:

1. `test_agent_permissions_are_scoped` names the grants that break isolation and excludes them: `shared = {"_INBOX.>", "$JS.API.INFO", "$JS.ACK.>"}`. The word "shared" was doing the work of a security argument.
2. `test_bitemporal_replay` covers add, change, and remove, but never remove-then-return, which is the broken case.
3. `TestRunCmdCancellation` uses `sh -c "sleep 30"`, which the shell exec-replaces, so there is no descendant and the drain bug cannot appear.

Each test encoded the author's mental model rather than challenging it.

## Suggested order

1. Validate every server-supplied identifier at the boundary (`session_id`, `job_id`, `entry_id`) and make a closed NATS connection fatal to the process. Closes 1, 2, and the zombie/auth-abort variants in one change.
2. Fix the bitemporal reconciliation predicate (3) and add the remove-then-return test.
3. Tighten the NATS grants (4, 5): per-agent inbox prefix, drop the `.>` on consumer create, scope `$JS.ACK`. Rewrite the permission test to allow zero shared subjects.
4. Alert row before cooldown (6); job dispatch through the existing outbox pattern (7).
5. Windows COM result escape (8) and pacman id validation (9) before any Windows or Arch fleet.
6. Trust-anchor fail-closed (10) before wiring self-update at all.
7. Timestamp sanity bounds, `max_deliver` + dead-letter, supervision of every task, and a health endpoint that reports ingest liveness rather than `SELECT 1`.
